# 2026-11-27: touch works, quiet boot, 320x480 display

## Touch: the real bug was power management, not the driver

- After the touch fixes of 2026-11-26 (PMU LDO12 power, chip id 0x4e31,
  per-phone calibration, frame-length fix) the driver already delivered
  correct multitouch events (`getevent`: x 0..5000, y 0..7500, BTN_TOUCH
  down/up, 2 fingers). Android classified the device correctly
  (EventHub classes 0x14, InputReader source 0x1002, 640x960).
- Android still ignored every touch: `dumpsys power` showed
  `mPowerState=SCREEN_BRIGHT_BIT` without `SCREEN_ON_BIT`
  (`mLastScreenOnTime=0`). The T4 kernel is built without CONFIG_PM /
  Android wakelocks, so `/sys/power` does not exist,
  `libhardware_legacy` `set_screen_state()` fails, PowerManager never marks
  the screen on and InputDispatcher drops all touches.
- Fix (`extras/touch/touch4/t4-sys-power.sh`, run from
  `t4-dynamic-probe.sh` before the framework starts): tmpfs over `/sys`, the
  real sysfs directories bind-mounted back from a second sysfs mount
  (`/dev/sysreal`), plus writable dummy `power/state`, `wake_lock`,
  `wake_unlock`. Result: `mPowerState=15`, touch works from boot.
- `t4-ui-watch.sh` no longer loops every second after boot (service is
  `oneshot` in init.rc).
- Note: `zygote` is `oneshot` in this init.rc - killing system_server does
  not restart Android (`start zygote` by hand; kill leftover systemui /
  com.android.phone first).

## Display: why the UI felt slow

- No GPU: SurfaceFlinger renders in software (`debug.sf.hw=0`); the A4's
  SGX535 has no driver for this kernel.
- t4fb is a RAM shadow buffer. A kernel delayed work (0xC0032E1C) converts
  the whole 640x960 frame to the real framebuffer (0x0F700000, xRGB8888)
  and draws a debug text bar - **every 10 jiffies = 100 ms (HZ=100)**, so
  the screen showed at most 10 fps. Android used 32 bpp RGBX without page
  flipping (gralloc memcpy of 2.4 MB per frame on top).
- CPU is fine: APLL 800 MHz, measured ~780 MHz with a 1e9-cycle loop
  (BogoMIPS 531 is misleading). Kernel tick is 100 Hz periodic, no
  high-resolution timers (10 ms resolution).

## LOWRES kernel (`LOWRES=1 extras/build/build-bootkit.py phone`)

Binary patches to the prebuilt T4 kernel (no source available), new code
assembled from `extras/build/lowres-fb.S` into the space of the deleted
debug-overlay functions (0xC00334C4..0xC003374C, inside the kernel image,
so Linux never reuses it):

| site | change |
|---|---|
| probe 0xC000DBB8 | var 320x480, yres_virtual 960 (2 pages), 16 bpp RGB565, fix.ypanstep 1 |
| check_var 0xC00330AC.. | accept 320/480/320, yoffset 0..480 |
| set_par 0xC0032FEC | line_length = 320*bpp/8 |
| pan_display 0xC0032DBC | record yoffset, set dirty |
| worker 0xC0032EB8 | if dirty (or every 0.5 s): 2x scale page -> real fb |
| 0xC0032F08 | overlay call removed |
| 0xC0032F5C | worker period 10 -> 1 jiffy |

Android sees 320x480 (`ro.sf.lcd_density=160` in the touch4-lowres
initrd), page flips work (yoffset alternates 0/480), frames reach the
screen within ~10 ms. The QUIET build also removes the overlay bar.

## Touch 11 Hz -> 50 Hz (initrd-touch5-lowres)

- The driver's `ms(1)` = nanosleep; on this HZ=100 kernel without hrtimers
  each one takes ~20 ms, 3 per SPI transfer, 2+ transfers per frame.
- `extras/touch/touch5/t4-touch-input`: the 3 sleeps in `xfer` call a ~110 us
  busy-wait (function at 0x8784 over the debug `raw_hex`, loop count literal
  at 0x8794 = 30000), end-of-poll `ms(10)` -> `ms(1)`, `raw_hex` calls NOPed.
  Measured 50 Hz, 0 frame errors.
