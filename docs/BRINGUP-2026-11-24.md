## The working recipe

Artifacts (all in `artifacts/`):

- `limera1n.payload` — pod2g's 584-byte payload (syringe `limera1n.S` build)
- `iBSS.n92ap.img3` — stock iOS 5.1.1 iBSS (68,100 B)
- `iBSS.n92ap-pwn.img3` — same, DATA patched at three offsets (below)
- `openiboot-archeyr.img3` — archeYR's openiBoot binary (n90ap build; same
  A4 die, fine for console) wrapped in an unsigned IMG3 (ident `ibec`)
- `tools/oibc` — console client (archeYR/OiBC, built on the host)

Steps (from `tools/linux-stage1.sh` semantics, one pass):

    ./a4boot artifacts/limera1n.payload artifacts/iBSS.n92ap-pwn.img3 reset
    python3 tools/dfu-upload.py artifacts/openiboot-archeyr.img3
    tools/oibc                      # openiboot console

Boot chain: bootrom DFU -> limera1n pwn -> pod2g payload (installed at
0x8402B001 via heap spray) -> payload calls the bootrom's
usb_wait_for_image, GID-decrypts the IMG3 (DATA+KBAG) and boots iBSS ->
iBSS DFU (buffer at 0x4ff00000, max 0x100000) -> manifest+reset makes iBSS
image3-load and EXECUTE the uploaded image -> openiboot runs at0x4ff00000
and relocates itself to 0x0 (position-independent, see
arch-arm/entry.sx ArmReset) -> openiboot console.

## Why the old attempts failed (post-mortem)

1. Wrong stage-2 image. The pod2g payload wants the ENCRYPTED IMG3
   (it decrypts DATA via KBAG/GID itself); the old flow uploaded the raw
   decrypted .bin which fails the payload's tag search.
2. a4boot deviated from syringe: async-cancel stalling write (USB/IP
   workaround) and a missing irecv_finish_transfer. Fixed to match
   Chronic-Dev/syringe exactly (sync 10 ms timeout + reset + finish).
3. The old flow used "go jump 0x41000000" — stock 5.1.1 iBSS has NO
   command parser at all (no go/getenv strings). The only boot path is
   Apple's restore one: DFU upload + manifest + USB reset -> iBSS
   image3-loads and executes the image. Reversed from the binary.
4. iBSS's image3_load rejects unsigned images; TWO "untrusted permitted"
   policy checks (0x5b4a and 0x5d52 in decrypted DATA) gate it.
   Final patches to iBSS DATA (tools/img3_repack.py):
   - 0x5b1c: BL verify_shsh -> movs r0,#0; str r0,[r3]
     (this is powdersn0w/L1K's iBoot32Patcher --rsa patch, proven)
   - 0x5d52: beq.w fail -> nop  (insurance)
   - 0x8178: policy function -> movs r0,#1; bx lr (insurance)
   Re-encrypted with the published 5.1.1 iBSS KBAG key/iv.
5. The wrapper IMG3 needs Apple's tag framing: totalLen must equal the
   tag's real byte span (zero-padded), header ident = 'ibec' (u32
   0x69626563), sigCheck = dataSize. Plus the board's VERS/SEPO/BORD/CHIP
   constraint tags copied from the stock iBSS.
6. **openiboot itself**: our build from iDroid-Project/openiBoot hangs in
   early init (black screen, pre-display; likely clock_setup spin loops).
   archeYR's fork (https://github.com/archeYR/openiBoot) has the fixes and
   boots perfectly ("openiboot 0.3 commit b0e6178b for iPhone 4").
