## Analysis (vmlinux 3.0.8 "peterdobby", built for IPOD_TOUCH_4G)
- machine_desc nr 3564 "Apple iPod Touch 4G" @VA 0xC001BA1C EXISTS:
  reserve=c000da5c map_io=c000da10 init_irq=c000d730 timer=c02722cc
  init_machine=c000da0c. So no "unrecognized machine" hang.
- board map_io: registers console "t4fb" (struct @c0274138, write fn
  c0032c54, flags PRINTBUFFER|ENABLED) using t4fb= cmdline (VA = PA+0xC0000000)
  and prints "T4_LINUX_RAM_01: Linux printk console active". Then cpu map_io
  c000d6f8: s3c-style init_cpu(0x8930), init_clocks(24 MHz) c000e13c, c000e224.
- t4fb console: 640x960 portrait, 80x120 cells, 8x8 font @c01f6904 (valid),
  WHITE TEXT ON BLACK, never fills white -> solid white is NOT the console.
  Prime suspect: clock init in cpu map_io gates/reprograms the display pipe
  -> LCD loses scanout -> white. (Unproven.)
- OUR BUG: m5..m10 painted PA FB via the head identity map; paging_init
  (prepare_page_table) wipes all mappings below the kernel -> m5's first store
  faults (no vectors yet) -> silent hang. So "olive then stop" is partly us.
- printk buffer: log_buf ptr/len pair @VA 0xC0275AA4 -> __log_buf
  VA 0xC028FCE0 = PA 0x0028FCE0, len 0x20000.
- reserve() also memblock_reserves PA 0x03F00000 (4 KB) — "T4_LINUX_RAM"
  area, possibly a persistent RAM log; worth dumping too.
